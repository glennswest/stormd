# Research — 2026-11-25 (stormcentral #628)

Window: since 2026-11-18. Read-only; no code changed. Method: `Cargo.lock` matched by script against a clone of [rustsec/advisory-db](https://github.com/rustsec/advisory-db) (b9b8a3c2c, 2026-11-25), `npm audit --package-lock-only`, crates.io and npm release dates, upstream GitHub advisories and release notes. ## 1. Upstream dependencies

### Affects stormd

- **tar 0.4.44**: [RUSTSEC-2026-0067](https://rustsec.org/advisories/RUSTSEC-2026-0067.html) (`unpack_in` can chmod outside the root) and [0068](https://rustsec.org/advisories/RUSTSEC-2026-0068.html) (PAX size ignored), March 2026, missed until now. The updater calls `unpack_in` on image layers. Fixed 0.4.45. **New: #106 (P2).**
- **russh**: new since 11-18, releases [0.65.3](https://github.com/Eugeny/russh/releases/tag/v0.65.3) and [0.65.4](https://github.com/Eugeny/russh/releases/tag/v0.65.4) (11-21). One is server-side: [GHSA-m6v5-wqxv-mffh](https://github.com/Eugeny/russh/security/advisories/GHSA-m6v5-wqxv-mffh) (handler callbacks after `channel_close`, affects <=0.65.3). The rest are client, agent or russh-config. RustSec also has 0492 (client side, fixed 0.63.1). **#63 target should be >=0.65.4**; commented. russh-sftp is at 4.0.0 (11-21); the vendored copy is 2.1.1.
- **rustls-webpki 0.103.9**: besides 0382, the database lists [0049](https://rustsec.org/advisories/RUSTSEC-2026-0049.html), 0098, 0099 (CRL and name constraints) and 0104 (CRL parse panic). All fixed by #76's >=0.103.16 (latest 0.103.17). Commented on #76.
- **url 2.5.8**: [RUSTSEC-2026-0592](https://rustsec.org/advisories/RUSTSEC-2026-0592.html) (11-20, stack overflow in `Url::origin()` on nested `blob:`), fixed 2.5.9. Via reqwest; stormd's crates do not call `origin()`. Low; added to #76's lock refresh.
- **web (build time only)**: vite 6.4.3 [GHSA-p4f5-76q4-ffq7](https://github.com/vitejs/vite/security/advisories/GHSA-p4f5-76q4-ffq7) (11-10, critical, dev server exposed with `--host`; our config does not set it), fixed 6.4.6; devalue 5.9.1 and source-map-js also flagged. **New: #107 (P3).**
- **chrono**: [RUSTSEC-2026-0543](https://rustsec.org/advisories/RUSTSEC-2026-0543.html), unmaintained (09-14). **New: #108 (P3).**

## 3. Techniques for open issues

- #65 (a line cut in two under a burst): the CRI log format marks a split record partial (`P`) and its end full (`F`), and the reader joins them, with a size cap ([Promtail's cri stage](https://grafana.com/docs/loki/next/clients/promtail/stages/cri)). The same shape would let capture flush an over-long or unfinished line without presenting it as two lines. Whether that is the cause of #65 was not checked.
- Others: nothing new.
